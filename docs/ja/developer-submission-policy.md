# 開発者提出ポリシー

CardputerZero AppStore は安全で透明性があり、継続的に保守できる registry を目指します。提出されるアプリはユーザー、デバイス、メンテナー、オープンソースライセンス、適用法を尊重する必要があります。

## 基本要件

開発者は次を行う必要があります。

- 正確な metadata を提出する。
- アプリの目的を説明する。
- データアクセス、デバイスアクセス、ネットワークアクセス、外部機器要件を宣言する。
- 動作するアイコンを提供し、可能ならスクリーンショットを提供する。
- 有効な `.deb` URL と checksum を提供する。
- ソース公開度、license、商用利用制限を宣言する。
- メンテナー審査に誠実に対応する。
- アプリ動作や URL が変わったら metadata を更新する。

## Metadata の正確性

アプリは以下を隠したり誤解させたりしてはいけません。

- 個人データ収集。
- ネットワーク動作。
- カメラ、マイク、GPS、センサー、ファイル、キーボード、外部機器アクセス。
- バックグラウンドサービス。
- 有料機能、商用制限、license 制限。
- 既知の高 CPU、ストレージ、バッテリー、デバイスリスク。

後続バージョンで動作が変わる場合、release 前または同時に metadata を更新する必要があります。

## プライバシー

ユーザーデータにアクセス、保存、アップロード、処理するアプリは以下を説明します。

- アクセスするデータ。
- 必要な理由。
- データがデバイス外へ出るか。
- 受信者。
- 保存期間。
- ユーザーが削除できるか。
- 第三者へ共有されるか。

不要なデータ収集は拒否または掲載停止につながります。

## デバイス安全

アプリはデバイス、システムファイル、ユーザーデータ、外部ハードウェアを意図的に損傷してはいけません。

ストレージ、システム設定、ネットワーク、GPIO、センサー、電源、音声、表示、外部モジュールに触れる場合はリスクを宣言してください。

拒否理由の例：

- 未宣言のデバイス不安定化。
- 明確な同意なしのユーザーデータまたはシステムファイル破損。
- 復旧手段のない永続的な動作変更。
- 過熱または不合理なハードウェア負荷。
- 高リスク動作の隠蔽。

## ユーザー体験

アプリは基本的な利用品質を満たす必要があります。

- APPLaunch または実機 AppStore から起動できる。
- 認識できるアイコンがある。
- 320 x 170 画面に収まる。
- 明確な終了方法がある。
- 通常起動で即時クラッシュしない。
- 欺く UI を避ける。
- 実験的、未完成、特殊設定が必要な場合は明記する。

## 禁止内容

メンテナーは以下に関係するアプリを拒否、非表示、掲載停止、block できます。

- 違法行為。
- マルウェア、スパイウェア、認証情報窃取、無許可永続化、無許可アクセス。
- 未宣言または不合理なデータ収集。
- ヘイト、嫌がらせ、追跡、詐欺、フィッシング、なりすまし。
- 著作権、商標、license 侵害。
- 武器化、監視、標的化、危害用途。
- 隠された有料機能または商用制限。
- 隠されたデバイスまたはデータ破損リスク。
- registry 審査またはインストール方針の迂回。

これは網羅的な一覧ではありません。安全、法律、プライバシー、コミュニティに明確なリスクがあれば拒否できます。

## 審査と異議申し立て

メンテナーは metadata 変更、package 変更、実験的ラベル、追加説明、スクリーンショット、テストログ、再現可能ビルド、手動デモを要求できます。

開発者は Issue または Pull Request で拒否、掲載停止、blocked の判断に異議申し立てできます。アプリ UUID、タイトル、変更してほしい判断、修正説明、証拠を含めてください。

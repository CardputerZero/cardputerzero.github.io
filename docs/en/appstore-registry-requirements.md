# AppStore Registry And Web UI Requirements

This document defines the first static CardputerZero Hub registry and website requirements.

## Goal

The Hub is a GitHub Pages friendly app catalog. It reads generated registry files, displays CardputerZero apps, supports search and filtering, and gives the on-device AppStore a stable online registry source.

The expected workflow is:

1. Developers build APPLaunch-compatible ARM64 `.deb` packages.
2. Developers run strict prepublish checks and publish through `czdev publish`.
3. `czdev` opens a Pull Request in `CardputerZero/packages` with the `.deb`, `meta.json`, icon, and screenshots.
4. GitHub Actions validates package metadata, assets, checksums, and APT index output.
5. Maintainers review risk, privacy, device safety, and user experience.
6. After merge, the packages repository rebuilds the APT index.
7. This Hub syncs package metadata into `generated/registry.json` and publishes it through GitHub Pages.
8. The device AppStore refreshes the registry and installs approved `.deb` packages.

## Static Hosting

The site must remain fully static:

- No backend service is required.
- GitHub Pages is the default hosting target.
- Registry files are generated by automation.
- Browser-side JavaScript handles search, filters, pagination, details, comments, and document rendering.

Current routes use hash routing such as `#/apps/<uuid>`, `#/documents`, and `#/tutorial`.

## Registry Files

The generated files have different roles:

- `registry.json`: canonical registry for the Web UI and on-device AppStore.
- `registry-index.json`: compatibility alias for older AppStore clients.

The device AppStore should tolerate network failure and show a clear error when registries cannot be loaded.

## App Metadata

Each app should provide source-side `app-builder.json` store metadata and package-side `pool/main/<package>/meta.json`.

Required app information:

- Stable UUID and unique share code.
- Title, summary, description, localized `locales` / `i18n` text, categories, and author GitHub ID.
- Version, license, source openness, and source repository.
- Debian package name, `.deb` URL, MD5 checksum, and package-relative icon and screenshot paths.
- Permissions, privacy behavior, external hardware, background service, HDMI, commercial use, and risk flags.
- APPLaunch metadata when relevant.

Downloads must be Debian `.deb` files. The device downloads to local storage, verifies MD5, and installs only entries whose review status is `approved`.

## APPLaunch Compatibility

Registry entries should describe apps that can be installed and launched through APPLaunch.

Reviewers should check:

- `.desktop` entry has required fields.
- `Exec` points to an installed executable.
- Icon path is valid.
- GUI fits 320 x 170.
- App exits back to launcher.
- Framebuffer behavior respects `LV_LINUX_FBDEV_DEVICE`.

## Internationalization

The Web UI supports:

- Simplified Chinese: `zh-CN`
- English: `en`
- Japanese: `ja`

Navigation, buttons, filter labels, status text, empty states, tutorial copy, registry labels, and document cards must use i18n dictionaries. Markdown documents may have per-locale files with fallback to `zh-CN`.

Recommended app and admin UI behavior: support i18n in Simplified Chinese, Japanese, and English. The default language should follow the system language automatically. If the project includes a calendar management admin console, users should be able to switch language there, and that manual setting should override the system language.

## Responsive Design

The site must support phone, tablet, and desktop widths.

Minimum checks:

- 320px width does not create horizontal page overflow.
- Search, filters, app details, comments, and document pages remain usable.
- Long URLs, UUIDs, checksums, and package names wrap correctly.
- Document table of contents stacks above the article on small screens.

## CI Checks

Pull request automation should validate:

- JSON parsing for package `meta.json` and generated registry files.
- UUID and share-code uniqueness.
- Required metadata.
- Package-relative asset paths and image files.
- APT package name, `.deb` URL, MD5, and SHA256.
- Source repository URL when provided.
- Permissions, privacy, and risk declarations.
- Generated `registry.json` and the legacy-compatible `registry-index.json` alias.

CI is a first gate, not a full security audit.

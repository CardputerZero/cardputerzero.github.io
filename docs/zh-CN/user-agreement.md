# CardputerZero Hub 用户与开发者协议

本协议适用于浏览、下载、提交、维护或审核 CardputerZero AppStore Hub 中的应用、元信息、截图、二进制文件、评论和仓库活动。

提交应用即表示你已经阅读并同意本协议、开发者提交规范、隐私要求、设备安全要求和维护者审核流程。

## 适用范围

本协议覆盖：

- 应用元信息。
- 源码。
- Debian 包和其他二进制文件。
- 图标和截图。
- README。
- Pull Request、Issue、Discussions 和评论。
- registry 文件和生成后的静态页面。

Hub 是公开目录和 registry，不代表维护者对每个应用做了完整安全审计。用户安装前应查看权限、隐私、源码开放程度、下载地址、checksum、风险标记和审核状态。

## 开发者责任

开发者必须：

- 使用可追溯的 GitHub 身份提交。
- 确认自己有权分发代码、素材和二进制文件。
- 提供准确、完整的 metadata。
- 声明权限、隐私、网络、设备访问和外部硬件需求。
- 保持下载地址和 checksum 有效。
- 配合维护者 review。
- 应用行为变化时及时更新 metadata。

## 元信息真实性

开发者不得隐藏或误导：

- 网络访问。
- 文件系统访问。
- 麦克风、摄像头、传感器、GPS 或键盘使用。
- 后台服务。
- 外部硬件。
- HDMI 输出。
- 账号、支付或云服务依赖。
- 商业使用限制和 license 限制。
- 高 CPU、存储、电量或设备风险。

## 隐私和数据

如果应用访问、保存、上传或处理用户数据，必须说明：

- 访问什么数据。
- 为什么需要。
- 数据是否离开设备。
- 接收方是谁。
- 保存多久。
- 用户是否可以删除。
- 是否与第三方共享。

应用应遵守最小必要原则。不必要的数据收集可能导致拒收或下架。

## 设备安全

应用不得故意损坏设备、系统文件、用户数据、外部硬件或网络环境。

涉及存储、系统配置、网络、GPIO、传感器、电源、音频、显示或外部模块的应用，必须清楚声明风险。

维护者可以拒收或下架会造成未声明设备不稳定、数据损坏、永久改变设备行为、硬件过热或隐藏高风险行为的应用。

## 用户体验

应用应满足基本可用性：

- 能从 APPLaunch 或真机 AppStore 启动。
- 有可识别图标。
- GUI 适配 320 x 170。
- 用户不会被困在应用中。
- 正常启动不应立即崩溃。
- UI 不得故意欺骗用户。
- 实验性、未完成或需要特殊设置时必须明确标记。

## 审核、上架和下架

CI 通过不代表自动上架。维护者可以要求修改、补充声明、人工演示、可复现构建或测试日志。

维护者可以把应用标记为 `pending`、`ci-passed`、`approved`、`needs-changes`、`rejected`、`deprecated` 或 `blocked`。

明显带来用户、设备、法律、隐私或社区风险的应用可以被拒收、隐藏、下架或 block。

## 申诉

开发者可以通过 Issue 或 Pull Request 申诉拒收、下架或 blocked 决定。申诉应包含应用 UUID、标题、希望改变的决定、修复说明和相关证据。
